# Plan: Fix Resource Node Rocks Not Disappearing with Refineries

## Problem
In Empires Mod, `emp_resource_point` (logical node) and `emp_resource_point_prop` (visual rock model) are separate entities. They must be linked via Source Engine I/O connections so that when a refinery is built (node disables), the rocks hide, and when destroyed (node enables), they reappear.

Currently, the VMF writer (`src/vmf_gen.py`) creates both entities but does **not** wire them together, causing rocks to clip through refineries.

## Investigation
- The project uses **vmflib** (third-party, patched) for VMF generation.
- `vmf_lib.Entity` objects auto-register to the map upon construction (singleton `ValveMap.instance`).
- Entities have a `.children` list for sub-components.
- vmflib provides:
  - `vmflib.vmf.Connections` class (vmf_class_name="connections")
  - `vmflib.types.Output` class (stringifies to `"event" "target,input,param,delay,times"`)

Usage pattern:
```python
from vmflib.types import Output
conn = vmf_lib.Connections()
conn.children.append(Output("OnDisable", targetname, "Disable", "", 0, -1))
conn.children.append(Output("OnEnable", targetname, "Enable", "", 0, -1))
entity.children.append(conn)
```

## Risks & Mitigation
- Import conflict: vmflib's Output class already exists; no conflict expected.
- Connections must be attached to `resource_logic`, not `resource_prop`. Correct.
- Target name must match exactly; we use `model_targetname` variable directly.
- Order of outputs doesn't matter, but both OnDisable and OnEnable are required.

## Notes
- No other files need changes; ValveVMFWriter only handles terrain geometry.
- The existing targetnames (`Res_Model_{faction}_{i}` or `Res_Model_Neutral_{i}`) are already unique per node.
