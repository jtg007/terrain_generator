# Plan: Fix Race Condition in Layout Validation

## Problem

When a user rapidly adds bases or resources in the GUI, the distance validation fails silently - the user cannot generate a VMF but no error message is shown. This happens because:

1. Rapid UI updates cause `config_model.custom_resources` to be in an inconsistent state
2. Validation runs on a potentially stale `TerrainSpec` object created from `config_model.make_spec()`
3. Errors are captured in `layout_result.invalid_entities` but not displayed to the user
4. The "Generate VMF" button may remain enabled even when validation would fail

## Investigation

### Current Flow
1. User clicks to add resource → `on_resource_added()` is called
2. `validate_current_layout()` is called (line 1069 in terrain_generator.py)
3. Returns `invalid_entities` but doesn't show errors to user
4. When user clicks "Generate", validation runs again but can fail silently if resources are in invalid state

### Root Causes
1. **Race condition**: `config_model.custom_resources` list is mutated while PreviewWorker runs
2. **Missing error display**: `validate_current_layout()` returns data but UI doesn't show what went wrong
3. **No generation guard**: "Generate VMF" doesn't verify layout is valid before starting

## Implementation Steps

### 1. Show validation errors in UI
File: `tools/terrain_generator.py`

In `validate_current_layout()`, also return the error messages:
```python
def validate_current_layout(self):
    try:
        spec = self.config_model.make_spec()
        layout_result = spec.validate_layout()
        return layout_result.invalid_entities, layout_result.errors
    except Exception:
        return set(), []
```

Then in `on_resource_added()`, display errors:
```python
invalid_entities, error_msgs = self.validate_current_layout()
if error_msgs:
    self.lbl_validation.setText("\n".join(error_msgs))
```

### 2. Add generation guard
File: `tools/terrain_generator.py`

Before starting GenerationWorker, verify layout is valid:
```python
def generate_map(self):
    is_valid, msg = self.config_model.validate()
    if not is_valid:
        QMessageBox.warning(self, "Invalid Layout", msg)
        return
    
    # Also check layout validation
    spec = self.config_model.make_spec()
    layout_result = spec.validate_layout()
    if layout_result.errors:
        QMessageBox.warning(self, "Invalid Layout", 
            "Cannot generate: " + "\n".join(layout_result.errors))
        return
```

### 3. Synchronize resource list access
File: `tools/terrain_generator.py`

Use thread-safe access when reading resources for worker:
```python
def run_preview(self):
    # Wait for any running preview to finish first
    if hasattr(self, "preview_worker") and self.preview_worker.isRunning():
        self.preview_worker.wait(1000)  # Wait max 1s
    
    # Then get fresh layout data
    # ... rest of existing code
```

Same guard for `generate_map()`:
```python
def generate_map(self):
    # Wait for any running workers
    if hasattr(self, "worker") and getattr(self.worker, 'isRunning', lambda: False)():
        self.worker.wait(1000)
```
